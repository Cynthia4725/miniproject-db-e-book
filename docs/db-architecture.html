Database Architecture & Physical Schema

เอกสารสถาปัตยกรรมฐานข้อมูลเชิงลึก แสดงผังความสัมพันธ์ทางกายภาพ (Physical Schema) ระดับคอลัมน์ กฎการเชื่อมโยง Foreign Key (Cascading / Restrict / Set Null), กลไกการประมวลผลธุรกรรม ACID (Transaction Runner), และกลยุทธ์ลูกผสมระบุตัวตน (Hybrid Identity Strategy) ของระบบร้านหนังสือดิจิทัล Neon E-Book Store

Runtime & Execution Layer

Neon Serverless Client & Pool

สถาปัตยกรรม src/db/client.ts เชื่อมต่อผ่าน @neondatabase/serverless ที่ปรับแต่งสำหรับ Vercel Serverless Function โดยเฉพาะ:

  • Zero Connection Leak: อาศัย HTTP/WebSocket connection pooling ไม่ต้องกังวลเรื่อง Max Clients ตัน
  • Cold Start < 15ms: ไม่ต้องสร้าง TCP Handshake ใหม่ทุกครั้งที่เกิด Serverless Invocation
  • Sanitized Logging & Error Mapper: แปลง PostgreSQL Error Codes (23505, 23503, 23514) เป็นโดเมน AppError อย่างปลอดภัย

Transactional Safety

ACID Transaction Runner

การทำงานแบบรวมศูนย์ใน src/db/transaction.ts ผ่านฟังก์ชัน runInTransaction<T>():

  • Atomic Checkout: สร้าง Record ใน orders และ snapshot ราคาสินค้าใน order_items พร้อมกันแบบ All-or-Nothing
  • Fulfillment Entitlement: อนุมัติสลิปโอนเงิน (payments.status='APPROVED') พร้อมออกสิทธิ์ใน user_library ทันทีในธุรกรรมเดียว
  • Automatic Rollback: หากเกิดข้อผิดพลาดใด ๆ ระบบจะสั่ง ROLLBACK ทันที ป้องกันข้อมูลค้างสถานะไม่สมบูรณ์

Relational Integrity

Hybrid Identity & 3NF Normalization

สถาปัตยกรรมโครงสร้างข้อมูลที่ผสมผสานประสิทธิภาพและการป้องกันภัยคุกคาม:

  • BIGINT Primary Keys: ทุกตารางใช้ IDENTITY BIGINT สำหรับการทำ B-Tree Indexing และ JOIN ที่รวดเร็วสูงสุด (O(1))
  • UUID v4 Public Identifiers: orders.order_number และ download_tokens.token ใช้ UUID เพื่อป้องกัน Insecure Direct Object References (IDOR)
  • Strict 3NF/BCNF: แยกความสัมพันธ์หนังสือ-หมวดหมู่-ผู้แต่งด้วย Junction Tables และตัด Transitive Dependency ทั้งหมด

ผังโครงสร้างข้อมูลกายภาพ (Physical Relational Schema SVG)

แสดงตารางจริง ชนิดข้อมูล SQL, ชิปข้อกำหนด (Constraints), และจุดเชื่อมต่อ Foreign Key ระดับคอลัมน์ (Column-Level FKs)

1. books Catalog Anchor

ตารางหลักเก็บรายการ e-Book ทุกเล่มในร้าน ควบคุมสถานะการวางจำหน่าย และเชื่อมโยงไฟล์ดิจิทัลที่ปลอดภัย

คอลัมน์สำคัญชนิดข้อมูลข้อจำกัด / หมายเหตุ
idBIGINTPK (GENERATED ALWAYS)
titleVARCHAR(255)NOT NULL ชื่อหนังสือ
publisher_idBIGINTFK -> publishers (SET NULL)
priceNUMERIC(10,2)CHECK (price >= 0)

2. users Security / Auth

เก็บข้อมูลผู้ใช้งานทั้งลูกค้าและผู้ดูแลระบบ รหัสผ่านเข้ารหัสด้วย scrypt cryptographic hashing

คอลัมน์สำคัญชนิดข้อมูลข้อจำกัด / หมายเหตุ
idBIGINTPK (GENERATED ALWAYS)
emailVARCHAR(255)NOT NULL UNIQUE
password_hashVARCHAR(255)crypto.scrypt Salted Hash
roleVARCHAR(20)CHECK ('customer', 'admin')

3. orders Hybrid Identity

แกนกลางของการสั่งซื้อ ใช้ Hybrid ID: id สำหรับการ JOIN ภายใน และ order_number (UUID) สำหรับสาธารณะ

คอลัมน์สำคัญชนิดข้อมูลข้อจำกัด / หมายเหตุ
idBIGINTPK ใช้ในระบบเชื่อมโยงภายใน
order_numberVARCHAR(64)UUID v4 ป้องกันการสุ่ม URL
user_idBIGINTFK -> users (ON DELETE RESTRICT)
order_statusVARCHAR(30)PENDING, PAYMENT_SUBMITTED, PAID

4. order_items Price Snapshotting

บันทึกราคาหนังสือ ณ วินาทีที่สั่งซื้อ (Frozen Unit Price) เพื่อไม่ให้กระทบยอดขายเมื่อราคาหนังสือในแคตตาล็อกเปลี่ยนแปลง

book_idBIGINTFK -> books (RESTRICT)
